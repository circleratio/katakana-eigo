# 要件定義

## 概要
英語の文章をカタカナに変換するツール。

## 機能要件
- 入力された英語の文章を、カタカナ表記に置き換える。
- 単なる綴りの機械的な変換ではなく、実際の発音(発音記号・音声)に最も近くなるようなカタカナ表記に変換する。
- 発音の基準はアメリカ英語(米語)とする。
- 辞書やルールで発音が特定できない未知語(固有名詞・専門用語・造語など)は、綴りから発音を推定するルールによりベストエフォートでカタカナに変換する。処理は中断しない。
  - このフォールバックは綴りをそのまま転写するものではなく、綴りから発音(音素)を推定した上でカタカナに変換するものであり、上記「単なる綴りの機械的な変換ではなく」という方針と矛盾しない。
- 入力テキストに日本語など英語以外の文字が混在する場合は、英単語部分のみをカタカナに変換し、それ以外の文字はそのまま出力する。
- 元のテキストの改行・句読点・単語区切りなどのレイアウトは保持したまま、英単語部分だけを置換する。

## 動作要件
- CLI(コマンドラインインターフェース)で動作するフィルタとして実装する。
- 入力は、標準入力、または引数に指定されたファイルから読み取る。
  - ファイルパスが引数で指定された場合はそのファイルを読み込む。指定がない場合は標準入力から読み込む。
- 出力は、変換後のテキストを標準出力に書き出す。
- 入出力の文字エンコーディングはUTF-8とする。

## 確定した事項(設計・実装により解消)
- 指定ファイルが存在しない・読み込めない場合のエラーメッセージ、終了コードの仕様
  → spec.md 6章の通り実装。存在しない場合は終了コード1でエラーメッセージを標準エラー出力へ出す。
- `--help` 等のCLIオプションを用意するか
  → 用意する(`argparse` 標準機能)。
- 出力先をファイルに指定するオプション(例: `-o`)を設けるか
  → v1では設けない(常に標準出力へ書き出す)。spec.md 8章の今後の課題として残す。
- 大文字小文字や強勢(アクセント)の違いを出力(長音・促音の付け方など)にどこまで反映するか
  → 大文字小文字は区別しない(カタカナに大小の概念が無いため)。強勢は母音の種類選択には使わず、二重母音・長母音かどうかで自然に長音が決まる設計とした(詳細は spec.md 3.5/3.6、`katakana_eigo/kana.py` を参照)。
  → この決定により、大文字表記(全て大文字など)を手がかりに頭字語・略語を検出することは原理的にできなくなる。そのため後述「略語・頭字語を1文字ずつ読み上げる特別ルールを持たない」点は、v1で未実装というだけでなく、この設計を変更しない限り解消できない恒常的な限界である(下記「既知の限界」参照)。
- ハイフンで連結された複合語(例: "well-known", "state-of-the-art")の単語判定
  → ハイフンを含めて全体を1つの英単語トークンとして扱う。分割せず、まとめて発音推定・カタカナ変換の対象とする。
- 単語内にアルファベットと数字が混在する語(例: "g2p")、およびハイフンと数字が混在する語(例: "COVID-19")の単語判定
  → アルファベット・数字・ハイフン・アポストロフィから成る連続した文字列のうち、少なくとも1文字以上アルファベットを含むものを1つの英単語トークンとして扱う。数字のみから成る文字列(例: "123")は英単語とみなさず、変更せずそのまま出力する。
- 標準入力・指定ファイルの内容にUTF-8として不正なバイト列が含まれる場合の挙動
  → エラーとして扱う。指定ファイルの場合は既存の「エラー: ファイルを読み込めません: <path>」(終了コード1、標準エラー出力、spec.md 6章)のケースに含める。標準入力の場合も同様に、「エラー: 標準入力をUTF-8として読み込めません」を標準エラー出力へ出力し、終了コード1で終了する。

## 既知の限界(要件外・今後の課題)
- 変換結果は音声認識的な精度の再現ではなく、規則ベースのベストエフォートであるため、定着した外来語表記(例: "stop"→"ストップ")と一致しない場合がある。
- 略語・頭字語(例: "NASA", "USA")を1文字ずつ読み上げる特別ルールは持たない。単なる未実装ではなく、大文字小文字を区別しない設計(上記「確定した事項」参照)により大文字パターンからの頭字語検出自体が不可能なため、この設計を維持する限り解消できない。
- L と R はいずれもラ行として変換され、区別されない(標準カタカナの表現力の限界)。
